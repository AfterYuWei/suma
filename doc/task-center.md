# 任务中心使用说明

适用：`feat/task-center` 工作区的统一自动化实现。该版本仍在验收，生产上线要求见 [最终设计](task-center-final-design.md)，实际验证进度见 [PLANS.md](../PLANS.md)。

## 查看执行与历史

任务中心提供执行中、自动化、执行历史三个视图，共用“当前节点／控制平面／全部”范围。全局 CD 主任务位于控制平面，节点交付位于相应节点。当前节点尚未选定时先选择节点。

执行中与历史支持任务名称、摘要、类型或节点名称搜索，以及类型前缀、来源、规则和状态筛选。翻页从服务端读取，筛选或页大小改变会回到第一页。规则筛选包含已归档规则，以便继续追溯。节点子任务继承父任务的真实触发来源；有自身触发记录时优先使用自身记录。旧任务没有可靠关联时显示“未记录”。

点击任务查看结果、步骤、日志和父子任务。详情可以跨节点和当前列表范围跳转，也支持 `/tasks#任务ID` 深链。完整入参和结果 JSON 默认折叠；CD 与清理优先展示原业务证据、原 ID 和业务来源入口。结果记录异常单独提示，不改写业务执行状态。关闭详情后停止详情轮询。

## 配置四类自动化

| 类型 | 配置入口及约束 |
| --- | --- |
| 镜像更新 | 选定节点与托管 Compose 项目，设置仅检测或自动更新、服务范围、Cron 和 IANA 时区。仅手动规则不计算下次周期。保存周期不会自动开启已暂停规则；自动更新仍检查 CD 占用、配置、digest 和 Docker socket 授权。 |
| 存储清理 | 使用原清理策略编辑器，每日或每周执行；启用仍需节点名确认与删除授权。卷仅扫描，删除卷继续走手动确认流程。立即运行先读取真实预览。 |
| 全局 CD | 使用交付项目配置，保留 30–86400 秒检查间隔及业务 Webhook。仓库、首次确认、观察／手动／自动策略和多节点交付由原业务负责。 |
| 节点项目 CD | 使用节点项目 CD 配置，保留秒级间隔、Webhook、候选与首次应用确认。项目锁、部署模式及失败恢复继续生效。 |

中心与原业务页修改同一规则。表单首次加载完成后才初始化；编辑中的草稿不会被轮询覆盖。并发修改返回 409，保留草稿并提供明确的重新加载入口。重新加载会使用当前服务器配置重新初始化草稿。

## 暂停、手动运行与归档

- **暂停周期触发**只关闭定时器，已启用的 CD Webhook 保持有效。
- **暂停全部自动触发**阻止周期和 Webhook。已通过执行门禁的操作可以结束；需要停止时另行取消 Task。
- **恢复自动触发**重新进行业务校验。清理授权不会因中心开关而被自动授予。
- **立即检查**对两类 CD 只刷新候选；发布继续通过原业务确认。镜像自动更新和清理手动运行仍遵循原确认流程。
- **归档规则**停止未来触发并保留规则、触发和 Task 证据。仍有有效业务配置的清理和 CD 使用暂停；关闭业务配置后才允许归档。版本冲突时重新加载后重试。

规则显示下次时间、最近触发及有效状态。已停摆意味着周期或业务绑定失效，需要查看原因并明确编辑修复，不能按“已启用”理解。暂时节点离线或远端不可用保留正常周期，不额外排队重试。

## 解释为什么没有执行

规则菜单的“触发历史”查询该规则，自动化页的“全部触发历史”按当前范围查询，包含没有永久规则的临时请求。两处均支持来源、触发状态和服务端分页；全部历史还支持规则筛选。展开“查看触发快照”才读取完整证据。

| 触发状态 | 含义 |
| --- | --- |
| dispatching | 已认领，尚未绑定 Task。 |
| started | 已原子绑定 Task；实际执行状态查看关联 Task。 |
| skipped | 忙、暂停或错过窗口等原因未执行；原因码保留。 |
| start_failed | 业务启动前失败，可能没有 Task。 |
| interrupted | 启动中断或旧记录证据不完整；不会重放。 |

同一目标忙时跳过并推进周期，不排队。Cron 重启后跳过停机积压；CD 间隔最多做一次基于当前配置的检查。手动检查不改周期，暂停不等于取消，历史跳过也不等于业务执行失败。

## Demo 与验收边界

Demo 保留四类规则的共享配置版本、触发历史、分页及模拟结果，用于交互验证。数据位于模块内存中，重载页面会重新初始化示例。不存在的任务返回 404，不显示虚构成功；普通长操作也进入同一任务历史。它不连接实际 Engine，也不运行服务端周期扫描器。真实 PostgreSQL 升级、并发／race、Unix／mTLS／Agent Docker 与生产升级演练必须独立验收，不能用 Demo 或编译替代。
