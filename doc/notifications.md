# 通知中心

入口：设置 → 通知渠道；顶部铃铛打开站内消息。命令面板提供通知渠道和规则入口。支持飞书企业自建应用机器人、Telegram 和通用 Webhook。

## 渠道配置

单页侧栏配置凭证和接收目标。“保存渠道”只保存；“检查凭证”和“发送测试消息”分别展示结果。草稿有修改时先保存，失败会保留草稿并停止后续操作。Token、App Secret、Webhook URL、Authorization 和签名密钥加密保存，读取只返回已配置标记，编辑时留空保留。

### 飞书

1. 创建企业自建应用，开启机器人能力，填写 App ID 与 App Secret 并保存。一个应用对应一个渠道、一个长连接和最多 50 个接收目标。
2. 开通应用身份权限：`im:message:send_as_bot`、`im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`。侧栏提供可复制的权限 JSON。
3. 在事件配置中使用长连接接收并订阅 `im.message.receive_v1`。设置可用范围，创建并发布新版本；不需要公网回调地址。
4. 私聊机器人，或在群内 @ 机器人。文字、富文本、图片和文件等用户消息都可识别会话。勾选所需会话、填写备注并保存；高级选项支持手填会话 ID。
5. 选择测试接收目标，发送测试消息。每个目标独立显示结果。通过“选择通知订阅”创建规则，指定该规则的接收目标。

所有启用的飞书渠道都会建立长连接。连接成功只证明传输建立，不能证明权限、事件订阅或版本发布生效。页面区分连接状态、消息事件计数、会话识别结果和保存失败，提示完成平台配置。

### Telegram

填写专用 Bot Token 和通知会话 ID，可直接主动发送通知。“自动发现接收会话”默认关闭；开启并保存后通过长轮询识别会话，再手动选择通知目的会话。已有 Telegram Webhook 不会被重置；存在 Webhook 时提示使用专用机器人或自行处理平台配置。

### 会话发现行为

收到消息仅保存会话元信息和接收去重记录，不保存正文、不执行查询或操作、不回复命令。发现会话不会自动订阅通知。暂停、删除、替换凭证、关闭自动发现和服务关闭会停止相应连接；旧连接不能继续写入会话。

### Webhook 格式与签名

接收 JSON：`schema_version: 1`、`message`、`events`、`url`。每个事件包含 ID、类型、时间、严重程度、范围、节点／资源以及关联 Task、Release。

启用签名时，`X-SUMA-Timestamp` 是 Unix 秒，`X-SUMA-Signature` 为 `sha256=` 加十六进制 HMAC-SHA256，签名内容是 `timestamp + "." + 原始请求正文`。接收方应校验签名、限制时间偏差，并按事件 ID 去重。外部投递为至少一次语义，超时可能造成重复消息。

## 事件、规则与发送记录

事件目录覆盖账户安全、节点与 Agent、容器与 Project、镜像更新、持续交付、存储清理、任务及通知渠道故障。密码登录必须完成 MFA 才产生成功通知。首次登录 IP 独立记录；同一身份或 IP 五分钟五次登录失败触发安全事件。

规则提供账户安全、重要异常、镜像更新、发布动态和清理报告预设，可按事件、严重程度、节点／节点组、Project 选择多个渠道及备用渠道。支持即时、五分钟合并、按 IANA 时区的每日摘要、跨午夜静默时段、临时静默和恢复通知。critical 事件及 CD 待审核事件绕过静默。消息模板只替换固定字段，不执行脚本。

同一资源同类异常十分钟内合并，镜像事件按目标 digest 去重。Docker 事件流辅以状态核对；主动生命周期操作和对应 Project／CD 重建按资源关联，避免隐藏同节点的其他异常。节点连续两次离线观察后通知，恢复单独记录。主机磁盘容量不在首版范围内。

PostgreSQL 保存事件历史、每用户已读状态和投递队列。队列最多四个并发发送、单次 40 秒截止、一分钟租约，最多五次重试，指数退避并遵守平台 `Retry-After`。重启恢复未完成投递；失败可手动重发。单个摘要最多 200 个事件，正文最多 12 KiB，完整事件仍可在站内查看。备用渠道失败不递归生成备用任务，渠道失败事件不递归通知自身。


## 数据库与验证

本版本只支持全新 PostgreSQL 基线。表结构不兼容时返回 HTTP 503 / `20802` 并提示使用此版本初始化的新库；重启不会升级旧表，也不会自动删除现有数据。

运行 `go test ./...`、`go build ./...`，以及 Web lint、typecheck、单元测试、生产与 Demo 构建。浏览器回归为 `web/e2e/notifications.spec.ts`、`web/e2e/feishu-channel.spec.ts` 和 `web/e2e/operations.spec.ts`；隔离真实 Docker 检查使用 `doc/operations-smoke.sh`。

真实平台消息发送和事件订阅验收需要专用机器人凭证及明确的接收会话；受控投递、浏览器和 Docker 测试不替代真实平台验收。
