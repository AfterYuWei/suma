# 通知中心

入口：设置 → 通知渠道；顶部铃铛打开站内消息。命令面板提供通知渠道和规则入口。支持飞书企业自建应用机器人、Telegram 和通用 Webhook。

## 渠道配置

渠道侧栏分为“连接配置”和“通知订阅”，切换保留草稿，底部统一显示保存状态。保存时原子提交渠道、默认订阅及目标覆盖。“保存渠道”只保存；“保存并完成”保存成功后关闭。检查凭证及发送测试也会先保存修改；失败保留草稿，不继续检查、发送或关闭。进入订阅页签不会自动保存。

Token、App Secret、Webhook URL、Authorization 和签名密钥加密保存，读取只返回已配置标记，编辑时留空保留。

### 飞书

1. 创建企业自建应用，开启机器人能力，填写 App ID 与 App Secret 并保存。一个应用对应一个渠道、一个长连接和最多 50 个接收目标。
2. 开通应用身份权限：`im:message:send_as_bot`、`im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`。侧栏提供代码块内的复制按钮。
3. 在事件配置中使用长连接接收并订阅 `im.message.receive_v1`。设置可用范围，创建并发布新版本；不需要公网回调地址。
4. 私聊机器人，或在群内 @ 机器人。文字、富文本、图片和文件等用户消息都可识别会话。勾选所需会话，点击名称修改备注（Enter 确认，Escape 取消）；ID 单独显示。高级选项支持手填会话 ID。
5. 单目标直接测试，多个目标先选择，同名目标通过 ID 区分。目标保留独立测试结果。切换“通知订阅”选择已有规则，保存后开始订阅。

所有启用的飞书渠道都会建立长连接。连接成功只证明传输建立，不能证明权限、事件订阅或版本发布生效。页面区分连接状态、消息事件计数、会话识别结果和保存失败，提示完成平台配置。

### Telegram

填写专用 Bot Token 和通知会话 ID，可直接主动发送通知。“自动发现接收会话”默认关闭；开启并保存后通过长轮询识别会话，再手动选择通知目的会话。已有 Telegram Webhook 不会被重置；存在 Webhook 时提示使用专用机器人或自行处理平台配置。

### 会话发现行为

收到消息仅保存会话元信息和接收去重记录，不保存正文、不执行查询或操作、不回复命令。发现会话不会自动选中或订阅；勾选并保存为接收目标后，才使用“全部对话”配置。暂停、删除、替换凭证、关闭自动发现和服务关闭会停止相应连接；旧连接不能继续写入会话。

### Webhook 格式与签名

接收 JSON：`schema_version: 1`、`message`、`events`、`url`。每个事件包含 ID、类型、时间、严重程度、范围、节点／资源以及关联 Task、Release。

启用签名时，`X-SUMA-Timestamp` 是 Unix 秒，`X-SUMA-Signature` 为 `sha256=` 加十六进制 HMAC-SHA256，签名内容是 `timestamp + "." + 原始请求正文`。接收方应校验签名、限制时间偏差，并按事件 ID 去重。外部投递为至少一次语义，超时可能造成重复消息。

## 规则、订阅与接收目标

- **规则只筛选事件**：名称、事件类型、严重程度、节点／节点组、项目范围。可以先独立创建，不必指定渠道。账户安全、重要异常、镜像更新、发布动态和清理报告预设用于创建可复用规则。
- **渠道订阅规则**：在“通知订阅”搜索并勾选已有规则；勾选并保存后即生效，任意一条规则命中即可触发；规则没有单独的启用／暂停状态。未选规则表示不自动发送，仍可测试渠道。没有合适规则时，可在同一侧栏新建，保存后返回原配置对象并自动勾选；渠道草稿保留，规则保存不代表渠道订阅已经保存。
- **全部对话与独立配置**：飞书订阅的配置对象显示“全部对话”，代表渠道内所有已选会话共用的规则和发送策略；会话默认整套使用该配置。切换为独立配置时复制当前默认规则和策略；之后互不影响。恢复继承后整套使用当前默认值。独立配置不选规则可让该目标不接收自动通知。Telegram 和 Webhook 使用渠道默认订阅。
- **发送策略属于订阅**：即时、五分钟合并、每日摘要、订阅时区、静默、模板和备用目标共用一套策略，不按命中规则分别执行。默认即时发送、无静默、默认模板、无备用；UI 时区取应用当前设置。

例如，“重要异常”和“生产环境异常”同时命中一个容器 OOM，继承这两条规则的值班群只生成一份自动投递。独立订阅发布规则的开发群不接收该事件。

规则列表显示只读订阅位置，可跳转渠道。发送记录显示全部命中规则及其历史名称／版本、事件数、事件通知／备用／手动重发来源和投递结果。修改或删除规则不改写历史证据。列表支持独立搜索、分页和上下文操作；发送记录 API 目前返回最近 200 条，搜索和分页覆盖这批记录。

### 事件与范围

事件是 SUMA 已定义的变化，例如 `container.oom`、`node.offline`；勾选它决定哪些变化触发通知。恢复通知直接勾选对应恢复事件，没有额外恢复开关。

范围在事件之上筛选严重程度、节点／节点组和项目。空选表示不限制；节点和节点组取并集，再与事件、严重程度、项目等其他条件同时匹配。项目按名称精确匹配。全局事件没有节点时，限定节点范围的规则可能不会匹配它。模板不能创建事件或改变条件。

事件目录覆盖账户安全、节点与 Agent、容器与 Project、镜像更新、持续交付、存储清理、任务及通知渠道故障。密码登录必须完成 MFA 才产生成功通知；首次登录 IP 独立记录，同一身份或 IP 五分钟五次登录失败触发安全事件。

### 静默与配置修改

固定静默延后普通通知，再按合并／摘要策略发送；临时静默把期间的新投递标记为未发送，不自动补发。站内事件始终保留。先匹配规则，匹配后的 `critical` 等级或 `cd.awaiting_approval` 事件绕过静默、合并和摘要等待。订阅时区同时用于调度和消息中的事件时间。

**修改或删除规则，取消订阅，修改频率、静默和模板，只影响新事件。已排队消息使用入队时的不可变配置快照继续发送，不扫描历史事件补发。** 发送策略或渲染配置修改后，相同发送时刻的新事件使用新快照批次。暂停／删除渠道、移除或更换接收目标，取消相关待发送／待重试队列；发送前再次检查渠道和目标有效性。已经发出的平台请求不会撤回。

删除规则会在事务内解除所有当前默认／覆盖订阅，并更新受影响渠道版本。删除备用渠道或移除备用会话也会解除失效备用引用；旧队列快照保留，失效备用目标不会发送。并发修改触发版本冲突，编辑草稿保留，不覆盖另一份配置。

### 消息模板

留空使用默认格式。自定义模板可修改固定文字、换行、字段顺序或省略字段。侧栏提供示例数据预览，不发送通知。只支持以下六个精确占位符；未知占位符会被拒绝。

| 占位符 | 内容 |
| --- | --- |
| `{{title}}` | 事件自身标题；默认模板按渠道语言使用目录标题 |
| `{{message}}` | 事件描述 |
| `{{node}}` | 节点名称，全局事件可能为空 |
| `{{resource}}` | 资源 ID，无关联资源时为空 |
| `{{time}}` | 事件发生时间，使用订阅时区 |
| `{{url}}` | 事件详情链接；未配置公网地址时是相对路径 |

```text
[SUMA] {{title}}
节点：{{node}}
资源：{{resource}}
详情：{{message}}
发生时间：{{time}}
查看：{{url}}
```

模板不能执行条件、循环或脚本，也不能自行读取容器 CPU、环境变量等额外 Docker 数据。`{{severity}}` 等六个字段之外的变量不支持。

## 去重、队列与发送记录

自动投递按 **事件 ID＋渠道 ID＋接收目标** 去重，不包含规则 ID 或配置版本。PostgreSQL 唯一约束和事务锁保护并发入队，主路由与备用路由共享自动投递声明。摘要按目标、发送时刻和配置快照分组，每个事件独立保留全部命中规则证据。

同一资源同类异常十分钟内合并，镜像事件按目标 digest 去重。Docker 事件流辅以状态核对；主动生命周期操作和对应 Project／CD 重建按资源关联，避免隐藏同节点其他异常。节点连续两次离线观察后通知，恢复单独记录。主机磁盘容量不在首版范围内。

PostgreSQL 保存站内事件、已读状态、队列、事件投递关联及快照。最多四个并发发送、单次 40 秒截止、一分钟租约，最多五次尝试，指数退避并遵守平台 `Retry-After`。重启恢复未完成投递。单个摘要最多 200 个事件，正文最多 12 KiB，完整事件仍可在站内查看。

主投递尝试耗尽后，备用目标沿用原消息并即时发送，不重新匹配规则、静默或递归备用；失败状态与备用入队在同一事务内提交。同一事件已在备用目标拥有自动投递时，不重复创建。渠道故障事件不通知自身，也不递归产生故障事件。

手动重发创建独立记录并关联原记录、沿用原快照；不重新匹配规则，但要求当前渠道和目标有效。手动重发不占用自动去重声明。跨规则重复已被消除；平台超时后的至少一次投递仍可能重复，接收方可按事件 ID 去重。

## 数据库与验证

项目已上线生产，后续通知结构和配置变化必须通过增量迁移保留原渠道、规则、订阅、事件、待发送队列及历史证据；已发布的初始化基线不再改写。数据库结构不兼容时返回 HTTP 503 / `20802`，应核对部署版本和迁移登记。当前旧错误文案提到新库初始化，不构成清空生产数据的授权。Demo 使用独立的 v2 配置存储。

2026-10-11 本机曾在用户明确授权后完成一次定向恢复，随后按用户要求切回其重建的原库。生产旧库迁移后来由用户取消，用户表示自行重建并重新处理本次数据；之后以生产数据必须保留的约定为准。历史操作见 [PostgreSQL 运行说明](postgresql.md)。

运行 `go test ./...`、`go build ./...`，以及 Web lint、typecheck、单元测试、生产与 Demo 构建。浏览器回归包括 `web/e2e/notification-subscriptions.spec.ts`、通知列表／编辑／飞书场景及 `web/e2e/operations.spec.ts`；隔离真实 Docker 检查使用 `doc/operations-smoke.sh`。

真实平台消息发送和事件订阅验收需要专用机器人凭证及明确接收会话；受控投递、浏览器和 Docker 测试不替代真实平台验收。
