# CD 操作模型与前后端重构

状态：已完成；验收结果见 PLANS.md。此文取代 2026-11-14 方案中的侧边 Sheet、操作名称省略号和发布页独立自动化区块。

## 产品职责

- 项目头部：发布、自动触发总开关、更多项目操作。开关直接表达「自动触发」，解释周期及已启用 Webhook，暂停不取消已开始的操作。
- 已有项目的总开关只在项目头部出现；新建／首次关联时可以指定初始状态。设置保存后停留原处并隐藏临时读取的变量值，不强制跳回发布页。
- 发布页：当前节点运行、最近一次发布结果和必要的失败处理。长期配置不占用发布页区块。
- 设置：Git 来源、认证、Compose 文件、变量、目标节点、更新后的处理方式、检查周期、Webhook、超时及失败恢复。任务中心编辑的是同一规则，仍保留版本冲突保护。
- 发布 Dialog：一个项目的一次操作。版本选择、准备、预览、确认、进度、结果在居中 Dialog 中完成；Dialog 标识项目，支持关闭后重新打开和刷新后恢复。关闭不取消后台操作。
- 发布记录：只记录实际发布、重试和恢复；纯检查通过任务中心追溯。恢复基于历史证据，不把检查结果当作发布成功。

## 用户路径

点击「发布」进入项目 Dialog。默认发布已配置引用的最新版本，可在 Dialog 中选择已发现的 Git 版本。点击「准备发布」固定版本、配置、镜像和目标，审阅后确认；主按钮使用实际目标数量。没有变更时明确提示，需要用户选择重建才可提交。

项目存在正在准备、待确认或执行中的操作时，先恢复该操作，避免重复启动。明确选择其他版本或重新准备才创建新的预览。页面刷新后从服务端查找当前项目的操作；不同项目及节点项目相互隔离。

失败直接显示节点及原因。重试沿用原快照，只处理失败节点；应用修改后的设置需要重新发布。历史镜像缺失时明确为重新应用配置。恢复切回手动策略、保留卷及原历史的契约继续有效。

## 服务端合同

两个入口增加只读 `GET release-activity`，由所属领域服务验证项目，再基于已有 Task 和 ReleasePlan 返回当前操作。优先返回活动任务，其次返回尚未过期且版本匹配的待确认方案。响应只包含操作指针和安全请求信息，不含私有载荷、凭据或环境变量。

不新增表、不修改已发布迁移、不改变历史 ID。准备及确认继续使用既有任务、项目锁、固定快照、版本检查和幂等认领。前端不再通过 Git Release 状态猜测任务是否正在执行。

节点项目区分触发配置版本和发布输入：暂停自动触发不占用 Docker 项目锁、不使手动预览失效；Git、私有凭据、变量、目标、发布策略及恢复配置仍参与方案校验。升级前创建的短期节点方案需要重新准备，已发布历史及固定镜像快照继续保留。已使用的方案、过期方案及成功基线改变后的旧预览不会再次作为当前操作恢复。

## 验证

服务／HTTP 覆盖项目与节点隔离、认证、空状态、活动准备／发布、有效及过期预览、配置改变、刷新恢复及私有字段隔离。浏览器覆盖两个入口、不同语言及主题、桌面／窄屏、居中 Dialog、固定头尾与内部滚动、关闭重开和跨项目隔离。

按大改动执行完整 Go／Web 门禁、完整浏览器回归及独立真实 Docker 发布冒烟。测试使用已有环境和随机隔离 schema；尚未通过的检查如实保留，生产不部署。

## 验收结果（2026-11-15，授权 CNB 测试机）

- 完整 Go `go test ./...` 与 `go build ./...` 通过；Web lint、typecheck、production 与 Demo build、183 项 Vitest 通过。
- 六套浏览器回归共 495 项全部通过（主应用、项目服务、容器、概览、任务中心、任务中心 Demo）。
- 真实 Docker：Unix Socket、mTLS TCP、HTTPS-WSS Agent 三种传输下的任务中心节点 CD 与全局 CD 六项门禁通过；独立隔离引擎上的全局 CD 固定版本恢复通过，覆盖重复恢复时强制替换容器。
- 本地与远端 680 个源码文件 SHA-256 逐项一致。
- 测试环境适配（未改产品代码或断言）：嵌套 rootless 引擎看不到宿主共享目录，改为在引擎内同一绝对路径放置绑定源文件；测试进程直接调用的 compose CLI 需显式 `DOCKER_HOST` 指向隔离引擎，否则会查询外层守护进程。
- 本机未运行产品构建，生产未部署。
