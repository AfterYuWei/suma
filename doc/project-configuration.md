# Project 可视化配置工作区

## 私有镜像仓库认证

普通 Compose 项目的“拉取”“拉取并重建”和“应用当前配置”，在任务开始时按目标节点的当前授权匹配仓库凭据，使用 Compose 渲染后的镜像地址（包括 `.env` 插值结果）。只加载本次镜像涉及的仓库，未授权凭据及其他仓库的密钥不会使用。同一节点对同一仓库有多个候选时明确失败，需在认证中心保留一个匹配授权；不会随机选择账户。CD 仍使用其项目中明确选择的仓库凭据。

执行器通过仅本进程可读的临时 Docker 配置传递认证，命令结束即清理；不需要在目标节点手动登录仓库。任务中的“Registry authentication loaded from node grants”表示已加载凭据，仓库是否接受凭据仍由拉取结果确认。密钥及编码认证值在实时和历史日志中遮蔽。

CNB 的配置为：仓库地址 `docker.cnb.cool`，认证类型“用户名 + 密码／访问令牌”，用户名 `cnb`，密码填写具备相应私有仓库制品读取权限的访问令牌。“Docker 身份令牌”对应 `identitytoken`，不适用于普通个人访问令牌。参见 [CNB Docker 制品库](https://docs.cnb.cool/zh/artifact/docker.html)及[访问令牌说明](https://docs.cnb.cool/zh/guide/access-token.html)。

项目列表和命令面板的“新建项目”进入 `/projects/new`。新项目从空服务集合开始；填写项目名、确认当前节点后添加镜像服务。首次保存创建托管目录。已有托管项目和接管后的项目使用同一配置工作区；外部项目仍需先接管。

左侧以服务列表为主入口，显示服务名和镜像；选择服务后，右侧通过基础、端口、环境变量、网络与依赖、存储、健康检查、资源限制、高级标签页配置当前服务。标签页、字段名称、重启／健康／依赖选项、端口与存储映射按当前语言显示，中文界面仅显示中文文案，英文界面仅显示英文文案，不再并列英文副标题或源码字段名。已知保留配置也显示本地化名称；源码及实际项目／服务名、镜像引用、变量名和自定义配置键保留原文。小屏使用当前服务选择器。点击添加服务立即生成一条空服务配置，直接在同一个基础标签页填写名称、镜像与重启策略，其他服务标签页同时可用，不再有独立的添加表单。名称可留空，列表与标题依次显示“未命名1”“未命名2”（英文为 Unnamed 1、Unnamed 2）；Compose 使用合法的自动服务名 unnamed-1、unnamed-2，自动名称在填写提示中可见。自动名称从已有编号继续递增，避免覆盖现有服务；同一页面内重命名或删除后仍继续编号。填写、修改或清空名称时保留服务配置，并同步可安全识别的引用。名称输入支持 Enter 提交与 Escape 恢复，格式或重名问题就地显示。静态镜像引用省略 tag 时填写 `latest`，正确区分镜像 tag 与私有仓库端口；digest 和变量表达式保留原文。`restart` 使用下拉选择，未配置时不写入默认值；选择 `on-failure` 可填写最大重试次数。[Compose 服务字段语义](https://docs.docker.com/reference/compose-file/services/#restart)

基础页提供“副本数量”，未配置时显示 1，单纯查看不会写入默认配置；清空输入恢复 1，0 表示不运行该服务。输入须为非负整数，Enter 或失焦提交到草稿，Escape 恢复，未提交或无效输入纳入保存与离页保护。修改已有 `scale` 或 `deploy.replicas` 时沿用原字段；两者同时存在且数量相等时同步修改，保留注释和部署资源等其他设置。两处数量冲突、变量、锚点或复杂配置通过源码编辑。固定容器名称限制为单副本；配置多个副本前须清空容器名称。保存配置后执行“应用当前配置”或“拉取并重建”，副本数量才会作用于目标节点。[Compose 副本语义](https://docs.docker.com/reference/compose-file/services/#scale)、[固定容器名称限制](https://docs.docker.com/reference/compose-file/services/#container_name)

端口页面以“主机端口 → 容器端口”为主线，在同一行编辑发布端口、目标端口和协议，绑定地址按需展开。留空主机端口表示由 Docker 分配。可以连续添加，或批量粘贴 `8080:80`、`5353:53/udp` 等格式；批量内容全部有效后才写入草稿，错误不会产生部分映射。`expose` 独立用于服务内部端口。[Compose 端口语义](https://docs.docker.com/reference/compose-file/services/#ports)

每个服务有独立的 `environment` 值、网络连接和挂载。`.env` 是 Compose 插值变量池，不会自动注入所有服务；服务可以直接填写环境值，或显式选择 `.env` 变量生成 `${KEY}`。添加变量使用一个完整表单，支持批量粘贴和就地创建 `.env` 变量。第一版仍管理单个 `compose.yml` 和 `.env`；已有 `env_file` 通过源码保留和编辑。

源码页 `.env` 标签右侧的圆形感叹号可悬浮或键盘聚焦查看使用说明，包含 `environment` 显式引用、`env_file` 导入全部变量的 Compose 示例，以及保存后应用配置的提示。

服务内添加网络时，默认选择目标节点已有网络，也可以复用已配置网络或填写新网络名称，并明确决定是否保留默认网络连接。存储直接在页面内编辑“来源 → 容器路径”，类型、来源、目标与只读控制集中展示，支持连续添加；新增映射默认主机路径，打开表单不会写入默认挂载。命名卷的来源选择框同时列出已配置卷和节点已有卷，也可以就地填写新卷名称。新建只更新声明，部署时才创建资源；选择节点已有资源会生成 `external: true` 和原生 `name`。主机路径属于目标节点，新增或修改路径须填写不含插值的绝对路径。修改映射保留其未覆盖的高级选项与注释。

没有项目设置或独立的项目资源页面。服务的网络、存储和环境标签页分别完成资源连接、挂载和变量引用；环境标签页内可展开 `.env` 插值变量查看和修改原文可安全编辑的变量。Compose 所需的顶层网络／卷声明仍由服务配置自动维护，原有声明及高级选项保留；解除网络连接或移除挂载只修改当前服务的引用，不直接删除 Docker 资源。没有显式网络配置的服务使用 Compose 默认网络。

高级页将容器标签 `labels` 和日志驱动选项 `logging.options` 分为明确的配置区域。标签是容器元数据，例如 `com.example.role=api`；日志选项传给选定的日志驱动，例如 `max-size=10m`。两者都通过完整的键值表单添加，重复键不覆盖现有值；已有列表形式标签、注释及其他服务配置保留。未提交的键值纳入导航保护，敏感值默认遮罩。

所有服务配置 Select 直接使用 `@/components/ui/select` 的 shadcn/Base UI 原生组件和 `SelectGroup`，通过 `items` 显示选项名称；菜单沿触发框边缘展开、宽度匹配，字段使用 gap 布局以避免隐含表单控件导致额外间距。对齐行为参考 [shadcn Select](https://ui.shadcn.com/docs/components/base/select#align-item-with-trigger)。

`compose.yml` 和 `.env` 是唯一持久化的配置。表单从 YAML AST 派生，标量编辑替换原始范围，结构编辑仅重写最小父节点并保留未知子节点、注释、引号和顺序。切换模式不修改原文。锚点、别名和合并结构通过对应字段或配置组的源码入口编辑；表单不展开共享结构。复杂 `.env` 表达式、重复赋值和多行值通过源码编辑。

源码模式（英文界面为 Compose）提供完整 Monaco 编辑，右侧预览保持只读。敏感字段、源码和差异默认遮罩；查看已有敏感源码需点击显示。正在输入的源码发生语法错误时保留原文，显示行列位置并暂停可视化修改，修复后恢复。配置草稿只存在页面内存中；离页、刷新和切换节点会保护未保存内容。名称与映射的未提交输入也纳入离页保护，后台刷新不会覆盖它们；先修正名称、保存映射或取消输入，再进行项目校验、保存及部署。未命名服务本身已经写入草稿，不需另行确认添加。切换服务、配置标签或模式时，会保护仍未提交的输入。

保存只更新配置文件。可解析并通过安全与项目身份检查的草稿可以保存，完整 Compose 校验留给校验和部署阶段。部署先冻结草稿并校验，再审阅节点、动作、服务概览及相对已保存配置的差异；确认后保存并提交 Task。“拉取并重建”执行 `pull` 后 `up -d`，菜单中的“应用当前配置”执行 `up -d`。差异不预测实际重建范围。原有 Socket 双重确认、接管项目首次部署确认及 Task 取消／后台继续入口仍适用。

详情接口返回不透明 `revision`；保存和部署可传 `expected_revision`。版本冲突返回 `409`，页面保留草稿并提供比较与重新加载。旧请求可不传版本，但与新入口共享项目锁及运行中操作保护。两份配置成组准备与发布，第二份发布失败会回退第一份。Task 开始及各 Compose 阶段再次核对版本；运行期间拒绝配置写入。敏感 CLI 诊断在进入 Task 状态和历史日志前脱敏，复杂敏感环境表达式的输出保守隐藏。

### 操作进度

“拉取并重建”使用面向 PC 的横向宽弹窗，最大宽度 1120px、高度 640px，并受当前窗口大小约束。左侧显示“拉取镜像 → 重建并启动”阶段、失败原因及资源状态，右侧持续显示实时输出；两侧独立滚动，展开镜像层不会拉长弹窗。阶段切换以服务端的镜像就绪记录为准。镜像、容器及其他资源各自保留最新状态，镜像层详情按需展开。主视图不展示按输出行数估算的总百分比；层的字节总量已知时才展示该层当前下载／解压阶段的比例，未报告总量时只显示已知字节数。完成计数仅统计已报告资源，不推测镜像层与服务的归属，也不把启动完成视为健康检查通过。

失败原因直接显示，取消保留已完成的变更。底部操作区固定可见，“后台运行”关闭弹窗并继续任务；执行中可通过项目页的“查看任务进度”重新打开，不会重复提交操作。实时输出自动跟随新消息，向上滚动后保留阅读位置。专项浏览器验证：`npm --prefix web run test:project-services -- compose-progress.spec.ts`，使用模拟 API，无需真实节点。

运行中的下载／解压字节计数随任务状态每秒刷新，即使历史日志没有新增也会更新对应镜像层的输出；当前帧标记为“实时”，不生成历史时间戳或累加重复条目。历史日志已报告更新的阶段或更大的同阶段字节数时，保留历史记录，避免独立轮询的旧任务响应覆盖它。

```sh

npm --prefix web run build
npm --prefix web run build:demo
```
