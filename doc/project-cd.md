# 项目 CD：单节点交付模式

项目 CD 是当前节点项目的部署模式；菜单中的「持续交付」是批量多节点交付。两者共用单节点交付流程（拉取镜像 → 应用配置 → 健康确认），持续交付另外负责 Release、审批、多节点编排和结果汇总。GitOps 是项目 CD 使用 Git 保存配置和检查更新的机制，不是第三类项目后端。

项目仍使用原节点及 Compose 项目名，列表返回 `backend=compose` 和 `deployment_mode=manual|cd`。项目详情的「配置｜服务｜日志｜CD」中，CD 页负责关联仓库、同步、应用、自动触发、同步记录和切回手动模式。设置与持续交付共用同一套表单，只隐藏目标节点，目标始终固定为当前节点。全局持续交付的运行项目在 CD 页提供跳转，不能再独立关联仓库。外部项目先通过已有接管流程成为托管项目。

## 配置和变量

全部托管项目统一为「可视化｜源码｜.env」。手动模式可以编辑；CD 模式的 Compose 来自 Git，可视化和源码只读，源码可选择按顺序合并的文件。页面标明预览 Commit 和是否已应用。

CD 模式的 .env 页分别展示仓库环境文件和本地覆盖变量。CD 设置中的“手动环境变量”与配置 .env 是同一份本地覆盖变量，切换标签时保留同一份未保存草稿；在任一入口保存后另一处立即更新，版本冲突保留草稿。本地覆盖变量复用持续交付的加密表单、保留值语义及 KEY=VALUE 批量导入。值默认隐藏，主动读取会记录审计；隐藏或离开后清除读取缓冲。本地值优先于仓库环境文件，仅参与 Compose 插值，容器仍须显式引用。关联前审阅并导入原 .env；含插值或转义的旧文件先在手动模式中整理为实际值。

## 检查、应用和回滚

关联只保存配置并切换模式，不改变现有容器。首次应用必须先检查并审阅固定 Commit 和配置快照，再人工确认；仓库、引用或文件范围改变后重新要求人工确认。保存本身不提交部署任务。交付策略与持续交付一致：观察模式只生成候选，禁止发布和回滚；手动模式等待用户确认发布；自动模式在验证通过后发布。自动交付触发单独控制轮询和 Webhook，关闭时手动同步只生成候选。轮询默认每 300 秒检查，也可接收 GitHub、GitLab 或通用 Bearer Webhook；自动触发在下次周期使用已保存设置。首次应用前自动触发只能检查，不能自动部署；首次确认成功后，自动模式下的同步可以自动应用。

Commit 与配置指纹相同不会重复应用；同一失败快照等待人工重试或新输入。镜像标签内容变化不会单独触发部署，运行漂移不会自动修复。运行检查基于当前 Docker 容器、Compose 配置指纹、副本数量和健康状态；无法读取节点时显示未知，不推断运行正常。普通项目的镜像自动发布在 CD 模式暂停，旧排队任务在执行前也会检查模式。

仅部署预构建镜像，沿用持续交付的文件来源与部署限制：禁止越界文件、构建、include/extends、特权模式、Docker Socket 等；主机绑定路径须为非插值绝对路径且只读。Unix、mTLS TCP 与 HTTPS/WSS Agent 均通过控制平面的同一 ComposeRunner 执行，Agent 不运行主机命令。

每次检查、应用和回滚独立记录任务、操作者、Commit、配置指纹和结果。成功应用记录可回滚，执行前重新检查文件、节点和凭据授权，并先将交付策略切换为手动；轮询可继续生成候选，但不会继续自动发布。回滚会重新拉取并强制重建，保留数据卷；可变标签使用仓库当前镜像，只有固定 digest 才能恢复同一镜像内容。可选开启“部署失败时自动回滚”：Docker 部署失败后尝试恢复最近成功应用的冻结快照，重新校验其凭据与节点，拉取镜像并强制重建。失败交付与自动恢复分别留存记录，恢复结果不覆盖原失败证据；恢复后交付策略切为手动，避免重复自动发布失败输入。首次尚无成功快照、前置校验失败或任务取消时不会自动恢复。恢复本身也可能失败，页面按 Docker 实际运行态显示，不能推断完整运行旧配置。

## 统一交付记录

持续交付首页的“记录”汇总批量交付与所有节点项目 CD 的历史，包括检查、发布、回滚及自动恢复。既有记录直接参与查询，升级后无需重新部署。可按来源、操作、状态及项目／节点搜索，分页和时间排序对两类来源统一计算；同名项目通过来源与节点区分。

记录仍归属原项目，不创建批量交付项目或 Release。展开后可看 Commit、配置指纹、执行人、结果及任务日志；“查看项目 CD”先切换到原节点，再进入项目 CD。已删除节点的记录继续可查，任务证据保留。全局记录不读取环境变量明文或加密快照。

## 切回手动

先暂停自动触发，导出最近成功配置：合并 Compose 文件并保留插值，补齐当时有效的 .env，复制依赖文件并重写引用。通过渲染等价校验后才发布托管文件、解除只读；不执行 up/down，不改变容器。尚无成功应用则保留关联前的配置。未应用变量和设置不进入导出。

无法完整导出时保留 CD 模式。进程中断后运行记录标为 interrupted，相关自动化暂停，保留快照供检查及重试。工作树、依赖和历史不随退出模式删除，避免仍运行的容器失去文件来源；自动清理也保护历史快照引用的资源。切回手动后原镜像自动更新策略恢复。退出后不再将认证中心凭据计为活动使用；历史快照保留引用，执行历史回滚仍要求对应凭据存在且授权有效。

## API 与升级

配置接口前缀：`/api/v1/nodes/:nodeID/projects/compose/:name/gitops`，属于当前项目的 Git 来源能力。支持 GET/PUT 配置、POST test-connection/check/apply、GET preview、PUT automation、GET/PUT environment、GET environment/values、GET drift、GET records、POST records/:recordID/rollback 和 POST detach。写操作提交预期配置版本，应用还需固定候选 ID；冲突返回 409。长操作返回节点 Task，实时及历史日志沿用任务服务。

Webhook 为 `/api/v1/webhooks/gitops/:hookID`，必须通过现有签名或 Token 验证。自动触发关闭期间有效请求返回 `ignored:true`，不占用投递 ID；无效签名仍返回 401。

新增 `0008_project_cd.sql`，仅创建项目 CD 配置与操作记录表；既有手动项目和持续交付数据不转换，不修改旧迁移、加密密钥或历史证据。增量迁移 `0009_project_cd_policy.sql` 补充交付模式、自动回滚和记录来源；既有自动应用配置保留为 auto，其余为 manual，自动回滚默认关闭，历史快照不补造策略。Webhook Secret 可在同一表单轮换，项目凭据可仅加密保存在项目，也可保存到认证中心并只授权当前节点。升级前保留数据库、应用文件与原密钥；升级后核对旧账户、节点、凭据、持续交付和任务记录，再启用项目 CD。回退旧程序前先暂停自动化、完成任务并把项目切回手动模式；保留新表、迁移台账、工作树和原密钥，禁止重置生产数据库。

验证状态以 PLANS.md 为准。浏览器替代 API 和执行器测试不等于真实 PostgreSQL、Docker 或生产验收。
